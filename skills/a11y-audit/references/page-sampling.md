# 페이지 표집 (a11y-audit)

인증·감사는 사이트 전체가 아니라 **대표 페이지 표본**으로 판정한다. 유형이 다른 페이지는 접근성
문제 양상도 다르므로, 유형을 고루 포함하는 것이 핵심이다.

## 유형별 최소 1개
- **메인/홈** — 내비게이션·배너·본문 바로가기·자동재생
- **목록/게시판** — 반복 링크·"더보기"·표 구조
- **상세/본문** — 제목 구조·이미지 대체 텍스트·표
- **폼/신청** — 레이블·오류 안내·필수 표시·자동완성
- **로그인/인증** — 캡차·레이블·오류·인증 대안
- **검색·검색결과** — 결과 없음 안내·포커스 이동
- **팝업/모달을 포함한 화면** — 초점 관리·키보드 조작

## 표집 원칙
- 템플릿이 같은 페이지는 대표 1개로 충분(목록 100개 중 1개). 템플릿이 다르면 각각.
- 반응형이면 desktop·mobile 뷰포트를 별도 표본으로 취급.
- 로그인 뒤 화면은 `audit_url`의 `headers`(인증 헤더)로 접근하거나 로컬 재현 페이지 사용.
- 동적 상태(모달 열림, 오류 표시)는 그 상태의 페이지를 따로 감사.

## 규모 가이드
- 빠른 점검: 3~5개.
- 인증 자가진단: 유형을 폭넓게(중복 템플릿 제외). `estimate_cert_readiness`는 최대 50건까지 집계.
- `pageCount`에 실제 표본 총 수를 넣어 준수율 분모를 맞춘다.

## 7.2.2(3.2.2) 도움 정보 일관성
- 도움말·문의 링크의 상대적 위치·순서가 여러 페이지에서 일관되는지는 페이지 간 비교가 필요하다
  (단일 페이지 자동 검사로는 판정 못 함 — 수동). 여러 표본을 나란히 놓고 확인한다.
