# 웹 접근성 감사 보고서 템플릿

> `audit-report` 프롬프트가 이 형식으로 보고서를 작성한다. `{siteName}`·`{audience}`에 맞춰 채우고,
> 검사항목은 항상 **공식 번호(별칭)** `6.4.1(2.4.1)` 형식으로 인용한다. 자동 검사 결과는
> "전문가·사용자 심사 전 참고 결과"임을 반드시 고지한다.

## 1. 요약
- 대상: {siteName} (표본 N개 페이지)
- 종합 판정: 실패 / 검토 필요 / 통과 중 하나 + 한 문장 근거
- 자동 검사 커버리지·추정 전문가 준수율(추정치임을 명시)

## 2. 33개 검사항목 판정표
| 검사항목 | 자동화 등급 | 상태 | 비고 |
|---|---|---|---|
| 6.4.1(2.4.1) 반복 영역 건너뛰기 | 자동 | fail/incomplete/pass/manual/na | 실패 페이지 수·대표 원인 |
| … (33개 전부) | | | |

## 3. 우선순위 조치
자동·보조 등급 항목 중 준수율이 낮은 순으로. 각 항목마다:
- 검사항목 ID(별칭)·영향(critical/serious/…)
- 문제 요약, before/after 코드(가능하면)
- 영향받는 페이지·선택자

## 4. 수동·사용자 심사 잔여
- 자동 검사로 판정할 수 없어 사람이 확인해야 하는 항목 목록(검사항목 ID + 확인 질문)
- 장애 유형별(시각·청각·지체·인지) 사용자 평가 과업 예시

## 5. 인증 준비도
- `estimate_cert_readiness` 결과: 검사항목별 준수율, gaps, manualRemaining
- 품질인증 기준 수치(전문가 95%·사용자 100%·평균 90)는 인증기관 공지로 재확인 필요임을 명시

## 6. 면책 고지
- 이 보고서의 자동 판정은 전문가·사용자 심사를 대체하지 않는 참고 결과다.
- 인증 통과 여부는 인증기관의 전문가 심사·사용자 심사로 최종 결정된다.

## audience별 조정
- **developer**: 코드 수정안·선택자·before/after 중심
- **manager**: 우선순위·공수·리스크 요약 중심, 코드 최소화
- **certification**: 33항목 판정표·준수율·잔여 심사 항목 중심, 근거·출처 명시
