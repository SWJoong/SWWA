# 폼 접근성 점검 (a11y-review)

`get_checklist`의 `scope=component, component=form`으로 관련 검사항목 목록을 받을 수 있다.

## 레이블 — 7.3.2(3.3.2)
- 모든 입력에 대응 레이블: `<label for="id">` + `id`, 또는 `aria-label`/`aria-labelledby`.
- **placeholder만으로는 부족** — `k-placeholder-only-label`가 잡는다. placeholder는 예시일 뿐.

## 오류 안내 — 7.3.1(3.3.1)
- 오류 발생 시 어떤 필드가 왜 잘못됐는지 구체적으로. `aria-invalid`+`aria-describedby`로 메시지 연결.
- "오류가 발생했습니다"만 표시하지 말 것.

## 색·감각 의존 금지 — 5.4.1(1.4.1)·5.3.3(1.3.3)
- 필수/오류를 색으로만 표시하지 말고 텍스트("필수")·아이콘 병행.
- "오른쪽 빨간 버튼" 같은 감각 지시 대신 라벨 병기.

## 이름 안의 레이블 — 6.5.3(2.5.3)
- 버튼의 보이는 텍스트가 접근성 이름(aria-label)에 포함돼야. 시각 "검색"인데 `aria-label="submit"`이면 실패.

## 자동완성·반복 입력 — 7.3.4(3.3.4)
- 이름·이메일·전화·주소 필드에 `autocomplete` 속성. 반복 입력은 재사용 수단 제공.

## select 자동 이동 — 7.2.1(3.2.1)
- `<select onchange="location=...">`로 선택만으로 이동/제출하지 말 것 — `k-select-onchange`(수동 확인). 별도 이동 버튼 제공.

## 인증 — 7.3.3(3.3.3)
- 캡차 등 인지 테스트만으로 인증하지 말고 대안(오디오·이메일 등) 제공 — `k-captcha-detect`(수동 확인).

## 포인터 입력 — 6.5.1·6.5.2
- 드래그·스와이프 전용 조작에 단일 탭 대안, mousedown 즉시 실행 대신 클릭 완료 시 실행(취소 가능).
