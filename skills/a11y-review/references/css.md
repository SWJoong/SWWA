# CSS 접근성 점검 (a11y-review)

CSS로 인한 접근성 문제는 대부분 **렌더링 후에만** 판정된다 — 정적 `check_html`은 놓치므로
`audit_url` 브라우저 감사나 `check_contrast`로 보완한다.

## 명도 대비 — 5.4.3(1.4.3)
- 텍스트/배경 대비 4.5:1(큰 글자 3:1) 이상. 색상 쌍을 알면 `check_contrast`로 즉시 계산.
- 큰 글자 = 24px 이상 또는 18.66px 이상 굵게.
- placeholder·비활성 텍스트·연한 회색 조합이 흔한 실패.

## 초점 표시 — 6.1.2(2.1.2)
- `outline: none`/`outline: 0`만 두고 대안이 없으면 실패. `b-focus-visible`가 브라우저에서 잡는다.
- `:focus`/`:focus-visible`에 뚜렷한 outline·box-shadow·테두리를 준다.

## 타깃 크기 — 6.1.3(2.1.3)
- 대화형 요소 클릭 영역 최소 약 24×24px(6mm). `b-target-size-6mm`가 대각선 22.7px 미만을 잡는다(문장 속 인라인 링크는 예외).

## 색만으로 구분 금지 — 5.4.1(1.4.1)
- 오류를 빨간 테두리로만 표시하지 말고 텍스트·아이콘 병행.

## 콘텐츠 구분 — 5.4.4(1.4.4)
- 이웃한 카드·버튼을 여백·테두리·배경으로 구별(수동 확인).

## 애니메이션·움직임
- 초당 3~50회 점멸 금지 — 6.3.1(2.3.1). 자동 변경 콘텐츠는 정지 컨트롤 — 6.2.2(2.2.2), `b-motion-runtime`.
- `prefers-reduced-motion` 존중 권장.

## 요령
색상 값이 코드에 하드코딩돼 있으면 `check_contrast`로 바로 검증하고, 실제 페이지는 `audit_url`
(viewport desktop/mobile)로 렌더 상태를 감사한다.
